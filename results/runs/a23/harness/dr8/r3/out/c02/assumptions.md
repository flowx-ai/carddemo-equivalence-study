# CardDemo POSTTRAN assumptions

Calculation-only implementation: decoded inputs and returned datasets; no file I/O or durable restart. Each decision is listed even if this run did not exercise it.

| Decision | What was assumed | Wiki statement or absence |
| --- | --- | --- |
| A01 | Stop validation when the card cross-reference or account is missing; after successful lookups, expiry overrides over-limit. | posttran-sonnet-dr8.pdf pp. 3-4: BR01-BR04 and the lookup order conflict with the invalid-card/expired-account example. Follow the usable lookup chain; no account is available after a missing cross-reference. |
| A02 | Retain each incoming transaction number instead of allocating a new sequence number. | posttran-sonnet-dr8.pdf pp. 9, 23 describe sequence allocation; p. 3 BR09 uses transactionId for idempotency; p. 27 supplies no sequence starting value. The maker explicitly chose incoming numbers, a departure from the sequence wording. |
| A03 | A separate adapter supplies decoded daily transactions, accounts, cross-references and category balances; return datasets and assumptions text, not actual files. | posttran-sonnet-dr8.pdf p. 27 lists fixed-width inputs and output files. The maker explicitly accepted a calculation-only implementation, leaving file decoding and file creation to a separate integration. |
| A04 | Calculate monetary values in integer cents and output monetary fields as two-decimal strings. | posttran-sonnet-dr8.pdf p. 27 allows numeric or string amounts with at most two decimals; the wiki does not specify arithmetic precision. Integer cents and exactly two displayed decimals are implementation choices. |
| A05 | Preserve a caller-supplied processing timestamp; otherwise capture UTC once per invocation in YYYY-MM-DD HH:mm:ss.SSS000 form and reuse it for all postings. | posttran-sonnet-dr8.pdf p. 3 BR05 says processedTimestamp = now; p. 10 gives a 26-character timestamp. Exact format, timezone, per-record clock sampling and replay clock control are unstated. A fixed supplied timestamp enables repeatable replay. |
| A06 | Compare account expiration_date with the first ten characters of orig_ts as an ISO date; equality is not expired. | posttran-sonnet-dr8.pdf p. 3 BR04 compares account expiry strictly before the transaction original date. Extracting the ISO date from the timestamp is not specified explicitly. |
| A07 | Add the signed amount to the category balance, starting missing categories at zero; add nonnegative amounts to cycle credit and negative amounts, retaining their sign, to cycle debit. | posttran-sonnet-dr8.pdf p. 3 BR05 describes signed account/cycle updates and category upsert; p. 20 specifies category-balance delta. Zero initialization and adding that delta make the missing-row upsert explicit. |
| A08 | After a transaction number posts successfully, skip subsequent records with that same number within this invocation, count them separately and invent no reject reason; rejected numbers are not marked as successfully posted. | posttran-sonnet-dr8.pdf p. 3 BR09 requires transactionId idempotency but does not define repeated feed rows, which occurrence wins, or a duplicate reject reason. This is the invocation-local interpretation. |
| A09 | Replay requires original starting snapshots and the same supplied processing timestamp; no persistent checkpoint or cross-invocation posting ledger is maintained. | posttran-sonnet-dr8.pdf p. 3 BR09 describes restart after the last processed index. The maker accepted calculation-only scope without storage; this deliberately does not implement durable restart against already changed balances. |
| A10 | An empty decoded feed returns no postings or rejects, unchanged snapshots and a successful zero-count calculation; the adapter handles absent-file NO_DATA. | posttran-sonnet-dr8.pdf p. 19 maps missing/empty files to NO_DATA. The calculation receives decoded arrays, not file statuses; its empty-array success representation is an implementation assumption. |
| A11 | Report unreadable required calculation values as separate errors, keep that record atomic and continue others. Use status ERROR and assumed return code 12; invalid starting snapshots produce empty final datasets that must not be used. Error indices are original zero-based feed positions, or -1 for a snapshot error. | posttran-sonnet-dr8.pdf pp. 3, 17, 19 define business rejects, rewrite failure 109 and integration errors but not pure-calculation errors or an error return code. BR08 excludes rewrite failure 109 from rejects. No real storage writes occur here, so 109 cannot occur. No new business reject is invented. |
| A12 | Do not add business rejections for active status, customer records, card expiry, type/category reference catalogs or disclosure-group data; do not inspect filler bytes. | posttran-sonnet-dr8.pdf p. 3 BR01-BR04 defines the posting rejection checks. Other model fields and files on pp. 7-15 and 27 do not establish additional POSTTRAN rejection rules. The calculation reads only the values needed for posting and required output. |
| A13 | Return every account and category balance, including untouched records, plus new categories created during posting. | posttran-sonnet-dr8.pdf p. 27 explicitly requires every account and every category balance after posting; p. 3 BR05 requires creation of missing category balances. This output boundary is required rather than an uncertain business rule. |
| A14 | Keep digit identifiers as text for internal identity, canonicalizing account leading zeros for matching; emit integer account and transaction category/merchant identifiers where the contract requires them. Category-balance category codes remain four-character digit text. | posttran-sonnet-dr8.pdf pp. 7, 9-10 describe fixed-width string identifiers; p. 27 requires integer account identifiers and transaction cat_cd/merchant_id but does not specify category-balance cat_cd type. Internal text preserves identity; category-balance category text follows p. 10. |
| A15 | Reject rows retain original contract transaction values, including original processing timestamps, and add integer reasons with the exact unpadded descriptions; return structured rows rather than the legacy 430-byte image. | posttran-sonnet-dr8.pdf p. 3 BR01-BR06 supplies the four descriptions and original image plus trailer; p. 27 permits structured JSON and omitted trailing spaces. The separate adapter is responsible for byte decoding and no raw dump is returned. |
