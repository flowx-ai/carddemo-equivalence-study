# Assumption evidence (extracted verbatim from the posting script's assumption(...) calls)

1. **Assumed:** Receive all nine named input files as caller-supplied text and return datasets and this report as data, not physical files. _Basis:_ posttran-sonnet.pdf p.27: "One JSON file per output: a list of objects, in any order." Maker selected data-only delivery because generated-file delivery is unavailable.
2. **Assumed:** Decode consecutive fields in data-table order, with trailing filler of 178 account, 14 xref, 20 transaction and 22 category bytes; FlowX-only daily attributes are not encoded in legacy records. Layout parity remains unverified without full copybooks. _Basis:_ posttran-sonnet.pdf p.7: "Legacy FILLER (178 bytes) is dropped"; p.9–11 list fields and widths; p.11: "Same attributes as Transaction"; p.27 names copybooks but does not provide their complete offsets.
3. **Assumed:** Signed monetary fields occupy their declared digit count with implied two decimal places; accept digits or ASCII trailing overpunch {ABCDEFGHI / }JKLMNOPQR, compute in integer cents and emit two-decimal strings. Use S9(9)V99 width 11 despite the inconsistent amount example. _Basis:_ posttran-sonnet.pdf p.9: "amount Number (2 dec)" and "S9(9)V99"; its displayed example has a different digit capacity; p.10 describes signed overpunch for disclosure data, not posting input encoding; p.27 permits amount strings or numbers with at most two decimals.
4. **Assumed:** Accept LF or CRLF and one terminal line ending; an empty supplied file has no records, while missing files, wrong widths, non-ASCII data, invalid numeric/date fields and duplicate business keys fail the calculation with no partial datasets. _Basis:_ posttran-sonnet.pdf p.27: "one record per line, fixed width"; framing, malformed-data handling and duplicate snapshot keys are otherwise unspecified.
5. **Assumed:** Missing card stops validation with 100; missing referenced account stops with 101; with an account present, expiry 103 overwrites overlimit 102. Equality on limit or expiry passes. _Basis:_ posttran-sonnet.pdf p.3 BR-01–04 and p.4: "Validation order xref → account → limit → expiry"; p.4 invalid-card-plus-expiry example cannot be evaluated without a referenced account; BR-03 uses > and BR-04 uses <.
6. **Assumed:** Preserve feed transaction identifiers, reject duplicate feed identifiers as a fatal input error, and do not allocate a database sequence. _Basis:_ posttran-sonnet.pdf p.23: "the new id is allocated by a sequence"; p.27 supplies neither existing transaction records nor sequence state.
7. **Assumed:** Use a supplied run timestamp, otherwise current UTC time, formatted YYYY-MM-DD HH:mm:ss.ffffff with millisecond precision padded to six fractional digits. Preserve rejected records' original processing timestamps. _Basis:_ posttran-sonnet.pdf p.3 BR-05: "processedTimestamp = now"; p.10 specifies X(26) timestamps but no timezone or fractional precision; p.3 BR-06 requires the original rejected image.
8. **Assumed:** Work on copied snapshots; a replay must start from original snapshots, with the same supplied timestamp for identical results. There is no durable restart, database rewrite failure or reason-109 reject in this calculation. _Basis:_ posttran-sonnet.pdf p.3 BR-08: "Reason 109 (account rewrite failure) aborts the record and is not written to rejects"; BR-09 proposes a processed-index restart, but the selected data-only scope has no persistent store.
9. **Assumed:** Read and check the widths of every supplied file but decode only daily transactions, accounts, xrefs and category balances; do not add active-status, type/category-reference or card-record validation. _Basis:_ posttran-sonnet.pdf p.3 BR-01–05 enumerate posting checks; p.27 lists the additional chain input files but specifies no additional POSTTRAN rules for them.
10. **Assumed:** Use numeric account and category identifiers in category output like their corresponding contract fields, retain zero-padded strings internally, trim only trailing spaces, allow blank optional reissue dates and incoming processing timestamps, and accept ISO original dates/timestamps. _Basis:_ posttran-sonnet.pdf p.27 explicitly marks account acct_id and transaction cat_cd as int, but does not type category-output keys separately; p.7 makes reissueDate optional; p.10 lists timestamps without a complete encoding rule.
11. **Assumed:** A valid empty feed returns OK/0 and unchanged snapshots; any reject returns WARNING/4; malformed input or field overflow returns ERROR/12 with empty result datasets and zero result counts. _Basis:_ posttran-sonnet.pdf p.3 BR-07 specifies warning return code 4 and p.5 says "read = posted + rejected"; no empty-feed return code or malformed-input return code is prescribed. ERROR/12 is an explicit implementation default.
12. **Assumed:** Only a model drafts the report presentation; canonical assumption entries cannot change, and failed or invalid drafting falls back to a deterministic table with failure disclosed. _Basis:_ The maker requires each assumption and its wiki basis; the wiki specifies no report-generation mechanism. This is the confirmed explanation-only design, not posting behaviour.
