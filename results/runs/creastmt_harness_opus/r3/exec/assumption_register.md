# Assumption ledger (extracted verbatim from the workflow scripts' note() calls)

1. **transport**: Supply decoded text in files keyed by the four exact filenames; return extensionless statement line lists and assumptions.md together, not local filesystem files. _Basis:_ creastmt-opus.pdf p.13 permits returned strings/lists; input transport and storage locations are unspecified.
2. **invocation**: Run on request, without automatic scheduling or a date filter; all supplied transactions belong to this batch. _Basis:_ creastmt-opus.pdf p.2 names Scheduled Start without a schedule; p.13 supplies combined daily transactions without a statement date filter.
3. **encoding**: Assume single-byte printable ASCII text, not packed binary or raw EBCDIC; require exact record lengths including filler. _Basis:_ creastmt-opus.pdf p.13 says fixed-width text; pp.5-8 do not establish export encoding.
4. **newlines**: Accept LF/CRLF, remove one terminal empty line, and treat an empty file as zero records; reject embedded blank lines, lone CR and nonprintable/non-ASCII characters. _Basis:_ creastmt-opus.pdf p.13 says one record per line, without newline or malformed-line rules.
5. **money-decoding**: Use two implied decimals; unsigned digits or trailing overpunch {ABCDEFGHI for positive 0-9 and }JKLMNOPQR for negative 0-9. Reject decimal points, leading signs and binary bytes; normalize negative zero. _Basis:_ creastmt-opus.pdf pp.5,8 specify signed S9(n)V99, but p.13 does not define textual sign encoding.
6. **unused-fields**: Ignore filler; do not use SSN, government ID, birth date or phone numbers in outputs, model requests or diagnostics, or validate unused text business content. _Basis:_ creastmt-opus.pdf pp.6-7 identify sensitive fields; pp.14-15 omit them from statements.
7. **identifiers**: Match digit strings with leading zeros; print 11-digit account IDs and three-digit FICO in X(20). Card numbers must be 16 digits. _Basis:_ creastmt-opus.pdf pp.5-8 specify widths; pp.14-15 do not define numeric-to-X display conversion.
8. **keys**: Reject duplicate account IDs, customer IDs, cross-reference card numbers and transaction IDs. _Basis:_ creastmt-opus.pdf pp.5-8 name unique keys; duplicate-input handling is unstated.
9. **joins**: Join each transaction card through CardXref to its account; every cross-reference must resolve an account and customer, and every account needs a linked customer. Unresolved links fail the batch. _Basis:_ creastmt-opus.pdf p.7 describes CardXref links; missing-link handling is unstated.
10. **customer**: Choose the smallest linked numeric customer ID, not an inferred primary-holder indicator value. _Basis:_ creastmt-opus.pdf pp.6-7 supply links and an indicator, without addressee selection or indicator value semantics.
11. **coverage**: Emit one statement per account, including inactive accounts and accounts without transactions. _Basis:_ creastmt-opus.pdf p.4 requires a statement per account and zero-activity handling; no inactive-account exclusion.
12. **ordering**: Sort accounts numerically and transactions by ID, with input order breaking ties; duplicate primary keys remain invalid. _Basis:_ creastmt-opus.pdf p.13 requires printed order without defining sort keys.
13. **balance**: Print supplied current balance unchanged; do not invent opening balance, interest, minimum due or category balances. _Basis:_ creastmt-opus.pdf p.13 supplies post-interest accounts; pp.14-15 print current balance; p.11 broader PDF content is absent from contracted layouts.
14. **total**: Total EXP is the signed sum of every account transaction, without type/date/category/sign filters; no activity totals zero. _Basis:_ creastmt-opus.pdf p.14 names Total EXP without a formula; p.4 requires zero-activity statements.
15. **precision**: Use integer cents without rounding; reject unsafe integer sums and overflow beyond the nine-integer-digit output picture, including intermediate totals. _Basis:_ creastmt-opus.pdf p.14 defines two decimals and nine integer digits; rounding/overflow policy is absent.
16. **name**: Trim and join nonblank first, middle and last names with single spaces, fitting X(75). _Basis:_ creastmt-opus.pdf p.6 supplies names; pp.13-15 leave assembly unspecified.
17. **address**: Trim customer address lines 1 and 2 for X(50); join nonblank address line 3, state, country and ZIP with single spaces for X(80). _Basis:_ creastmt-opus.pdf p.6 supplies components; p.14 gives printed slots without assembly rules.
18. **details**: Use right-trimmed transaction description fitted to X(49), not merchant or type text. _Basis:_ creastmt-opus.pdf p.8 has description and merchant data; pp.14-15 do not define Tran Details assembly.
19. **pictures**: Balance uses 9(9).99-; amounts/totals use Z(9).99-. Negative sign trails; positive/zero sign is space. Zero-suppressed whole zero is nine spaces, then .00 for zero. _Basis:_ creastmt-opus.pdf p.14 defines pictures; zero rendering assumes COBOL picture semantics.
20. **text**: Use literal ordered text lines and repeated separators, headings even without activity, plain-text total and one start/end marker per account; no extra inter-statement blank lines. _Basis:_ creastmt-opus.pdf p.14 gives the line sequence but no inter-statement spacing.
21. **html**: Concatenate complete per-account HTML documents without extra separators, HTML totals or PDF generation. _Basis:_ creastmt-opus.pdf pp.14-16 give HTML blocks without a total; p.13 requires text/HTML, not PDF.
22. **escaping**: Use the same fitted field values in both outputs; HTML-escape &, <, >, double quote and apostrophe before fitting each HTML line. _Basis:_ creastmt-opus.pdf pp.14-15 specify fields but not escaping or whitespace assembly.
23. **line-fitting**: Right-pad text lines to 80 and HTML to 100; truncate excess at the right, even an HTML tag/entity. Return lists without embedded newlines. _Basis:_ creastmt-opus.pdf pp.13-15 fix line lengths and allow omitted trailing spaces, but give no overlong-substitution policy.
24. **errors**: Fail atomically on missing files, malformed records, invalid used numbers, duplicates, missing links or overflow; return file/line/field diagnostics without raw values or partial statements. Keep input files unchanged. _Basis:_ The wiki gives no malformed-input, partial-output or mutation policy for statement generation.
25. **documentation**: A documentation-only model copies this complete ledger into separate assumption/source fields, receiving no customer or transaction data; retain fields and render one Markdown row per decision. _Basis:_ Maker explicitly requires every assumption and its wiki statement or absence; the wiki gives no documentation-generation mechanism.
26. **documentation-failure**: If drafting fails or changes/omits/duplicates a decision or source, return failure without statements and render the original ledger as assumptions.md. _Basis:_ The wiki is silent on documentation failure; chosen to prevent undocumented successful output.
