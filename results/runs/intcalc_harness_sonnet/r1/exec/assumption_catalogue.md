# Sonnet r1 build: assumption catalogue, verbatim from the workflow script 'Calculate interest' (exec/workflow.md)

1. [delivery] This is a side-effect-free calculation over decoded records. It returns data and proposed assumptions.md contents, not physical files. Only newly generated interest transactions are returned.
   basis: intcalc-sonnet.pdf p.24 CONTRACT.md requires intcalc_systran.json and intcalc_acctdata.json; maker explicitly selected calculation-only delivery. p.2 BR-09 contrasts overwrite with append; no existing transaction input is provided.
2. [decoded] Inputs are four explicit arrays: accounts and balances use CONTRACT.md names, disclosure rows use group_id/type_cd/cat_cd/interestRate, and card links use acct_id/card_num. Annual rates are already decoded decimal percentages, not signed-overpunch text.
   basis: intcalc-sonnet.pdf pp.8-9 describe CardXref and DisclosureGroup and conversion at load; p.24 fixes output names, not decoded input property names.
3. [rounding] Truncate each category interest toward zero to two decimals before summing the posted amounts. Use exact integer cents with quotient/remainder decomposition, not binary fractional-cent arithmetic.
   basis: intcalc-sonnet.pdf p.2 BR-03 gives balance times rate divided by 1200; BR-08 says COBOL default truncation but explicitly leaves rounding confirmation and a golden-file test outstanding.
4. [zero-negative] Retain signs of negative balances and rates. A nonzero rate generates one transaction even if truncation yields zero; a zero rate generates none. Do not substitute DEFAULT for a found zero rate.
   basis: intcalc-sonnet.pdf p.2 BR-02 retries only a missing rate, BR-03 tests rate not zero, and BR-10 on p.3 states zero rates charge no interest. Negative inputs and zero after truncation are not further specified.
5. [order] Sort accounts numerically and category balances by account, type and category before allocating transaction identifiers. Reject duplicate natural keys rather than guessing which record wins.
   basis: intcalc-sonnet.pdf p.2 traverses balances by account and uses a running suffix; pp.6,8-9 define keys. Incoming order and duplicate handling are unspecified for decoded input.
6. [identifiers] Default interestRunDate to 2022071800. Require ten digits. Append a six-digit suffix starting at 000001 for each generated transaction, failing beyond 999999. Each invocation starts afresh and does not deduplicate prior runs.
   basis: intcalc-sonnet.pdf p.2 BR-05 gives the ten-digit prefix example plus a running suffix; p.8 defines a sixteen-character transaction id. Suffix width, initial value and rerun policy are not specified.
7. [card] Use the lexicographically lowest sixteen-digit card number linked to each account requiring an interest transaction. A required transaction with no linked card fails the run.
   basis: intcalc-sonnet.pdf p.8 defines CardXref by card with secondary access by account and makes transaction.cardNumber required. Which card an interest transaction selects and missing-link behavior are unstated.
8. [merchant] For system interest transactions set merchant_id to 0 and merchant_name, merchant_city and merchant_zip to empty strings.
   basis: intcalc-sonnet.pdf pp.2,8 specify interest metadata and required merchant fields without values for system-generated interest.
9. [timestamps] Default businessDate to 2022-07-18 and use business-date midnight for both transaction timestamps, in YYYY-MM-DD 00:00:00.000000 form. Do not use the wall clock.
   basis: intcalc-sonnet.pdf p.24 supplies the business date; p.9 specifies timestamps of length 26. No interest timestamp value or separator is documented.
10. [account-boundaries] Rewrite and reset cycle credit/debit to zero for every account represented in category balances, including zero-rate accounts and the final account. Leave accounts with no category balances unchanged.
   basis: intcalc-sonnet.pdf p.2 BR-06 rewrites at each account change, adding accumulated interest and clearing cycle totals. Accounts absent from traversal and the final flush are not explicitly discussed.
11. [metadata] Use type 01, numeric category 5, source System, and description Int. for a/c followed by the eleven-digit zero-padded account number. No fees are calculated.
   basis: intcalc-sonnet.pdf p.2 BR-04 specifies type 01/category 05/source/description; BR-07 says fees are an empty stub. Account-id padding in the description is inferred from p.6 9(11); p.24 requires category as an integer.
12. [validation] Require unique nonzero eleven-digit account ids and sixteen-digit card numbers; normalize numeric type/category codes to two/four digits and trim padded lookup strings. Require all contract account fields, valid calendar dates (blank reissue permitted), Y/N active status and two-decimal amounts within documented record widths. Reject malformed, duplicate, dangling or overflowing data as a whole, with no partial arrays; keep diagnostics and assumptions.
   basis: intcalc-sonnet.pdf pp.6,8-9 specify record types, widths and keys; p.24 allows omitted trailing spaces and amounts of at most two decimals. Detailed decoded-input validation and all-or-nothing returned output behavior are unstated; p.22 BR-02 stops the chain on a failing step.
13. [missing-default] If both the requested group rate and matching DEFAULT row are absent, fail rather than silently treating the rate as zero.
   basis: intcalc-sonnet.pdf pp.2,17-18 specify DEFAULT fallback but no behavior if DEFAULT is also absent.
14. [representation] Return exactly the contract account/transaction fields. Emit amounts as decimal strings with two digits after the point; account and merchant ids and category codes are integers. Emit strings without trailing padding and preserve card-number leading zeros. Reject unsafe accumulation or final record-width overflow.
   basis: intcalc-sonnet.pdf p.24 permits decimal strings or numbers and omitted trailing spaces and fixes identifier types. pp.6,8-9 give numeric widths; overflow and canonical decimal formatting are not specified.
15. [explanations] An AI step drafts only these explanation entries, never financial results, and receives only this catalogue. Require every id exactly once with separate assumption and wiki-basis properties. Pin citations to this catalogue. Missing, failed or structurally incomplete drafting fails the overall result, with clearly marked fallback notes and no partial arrays.
   basis: Maker requests each assumption and the wiki statement or absence behind it. The wiki does not specify explanation drafting or its failure behavior. This implementation isolates drafting from deterministic calculations; equivalence to COBOL remains unverified.
