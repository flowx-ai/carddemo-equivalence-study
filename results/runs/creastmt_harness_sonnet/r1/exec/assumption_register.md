# Assumption ledger (extracted verbatim from the workflow scripts' assume() calls)

1. **Input record offsets**: Fields occupy consecutive DISPLAY character positions in the wiki table order; account monetary fields occupy 12 characters and transaction amount 11, with no separate sign position; trailing record filler is ignored. Offsets are inferred, not verified copybooks. _Basis:_ creastmt-sonnet.pdf pp.6–9 list field pictures and widths; pp.25–26 name the copybooks but omit their complete definitions.
2. **Signed numeric encoding**: Accept numeric DISPLAY digits with implied two decimal places and ASCII overpunch {ABCDEFGHI for positive and }JKLMNOPQR for negative final digits. Also accept an explicit decimal point or a leading/trailing sign inside the declared width. Reject nonnumeric encodings. _Basis:_ creastmt-sonnet.pdf pp.6,8 specify signed monetary pictures but omit their physical input encoding.
3. **Record delimiters**: Accept LF or CRLF, ignore a single final line delimiter, require exact nonempty record widths, and treat an empty file as zero records. _Basis:_ creastmt-sonnet.pdf p.26 says fixed-width text, one record per line; newline conventions are unstated.
4. **Card selection**: Generate one statement per cross-reference card in lexical card-number order, matching transactions to that card alone and ordering them by transaction ID. Do not pool other cards of the same account or filter by dates. _Basis:_ creastmt-sonnet.pdf p.2 BR-01: CardXref order (card number); BR-02: card number + transaction id; p.3: legacy prints all transactions on file, cycle filter remains TODO.
5. **Customer name**: Trim each first, middle and last name, omit blank parts, and join the remaining parts with one space. _Basis:_ creastmt-sonnet.pdf p.7 lists firstName, middleName and lastName; pp.13,21 require customer name but do not define concatenation.
6. **Customer address**: Use trimmed customer address lines 1 and 2 directly; construct printed line 3 by joining nonblank addressLine3, state and ZIP with single spaces; do not print country. _Basis:_ creastmt-sonnet.pdf p.7 lists address fields; p.21 says address (3 lines, state, zip), without an assembly rule.
7. **Account and FICO display**: Preserve the zero-padded account identifier from the xref as text. Preserve a three-digit FICO score; a wholly blank FICO prints blank. Reject other FICO encodings. _Basis:_ creastmt-sonnet.pdf pp.6–8 give numeric identifiers and optional FICO; p.27 specifies account ID and FICO X(20) without conversion rules.
8. **Printed field truncation**: Truncate ordinary text fields on the right to the contract width and pad on the right with spaces; never truncate numeric output. _Basis:_ creastmt-sonnet.pdf p.27 gives X(n) and numeric pictures, but no overflow policy.
9. **HTML field safety**: Escape ampersand, less-than, greater-than, double quote and apostrophe in inserted HTML text. Fit insertions within 100 columns without splitting an entity, preserving literal tag suffixes; truncate only the inserted field when necessary. _Basis:_ creastmt-sonnet.pdf pp.27–29 specify literal HTML and 100-column lines but omit escaping and escaped-field overflow rules.
10. **Duplicate records**: Reject duplicate account IDs, customer IDs, xref card numbers or transaction IDs instead of choosing one record. _Basis:_ creastmt-sonnet.pdf pp.6–8 declare primary keys but do not specify duplicate input handling.
11. **Missing references**: Fail the whole batch if an xref has no matching account or customer; ignore transactions belonging to no listed xref because statements are xref-driven. _Basis:_ creastmt-sonnet.pdf pp.2,13 describe xref-driven joins, without missing-reference behaviour.
12. **Monetary arithmetic**: Decode and sum safe integer cents, preserve signs, print zero without a negative sign, and fail on values exceeding nine integer output digits or safe integer arithmetic. _Basis:_ creastmt-sonnet.pdf p.2 BR-03 defines sum of amounts; p.27 defines numeric pictures but not overflow handling.
13. **No extra printed sections**: Use only contract lines: no phone, credit limit, statement date, PDF, SSN or HTML total row, although the plugin sketch mentions additional content. _Basis:_ creastmt-sonnet.pdf p.21 is a broad content sketch; pp.26–29 define the required printed output and omit these lines.
14. **Batch failure and empty inputs**: Missing files, malformed records, broken joins and numeric overflow fail the batch without partial statements; present empty xrefs produce a successful empty statement set. _Basis:_ creastmt-sonnet.pdf p.23 says a failing step stops the chain; no statement-specific invalid-input or empty-xref policy is given.
15. **Output packaging**: Return ordered line lists under creastmt_statements and creastmt_statements_html with a companion assumptions.md string and structured assumptions entries; do not write host-directory files. _Basis:_ creastmt-sonnet.pdf p.26 explicitly permits returned line lists under file names without extensions and names optional assumptions.md.
16. **Assumptions drafting validation**: A model organizes only this ledger, never customer data; exact entry coverage and exact assumption/source preservation are checked before rendering Markdown. Draft failure or alteration fails the batch without partial statement outputs. _Basis:_ The request requires every assumption and its wiki basis; the wiki is silent about how the companion document is authored or validated.
