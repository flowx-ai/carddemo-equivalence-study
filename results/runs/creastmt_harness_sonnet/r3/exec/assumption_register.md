# Assumption ledger (extracted verbatim from the workflow scripts' fact() calls)

1. **ENCODING**: Interpret supplied file contents as decoded text, preserve leading zeros in identifiers, and decode signed numeric pictures as implied-decimal display digits with a final ASCII overpunch ({/A-I positive, }/J-R negative); a digit final character is positive. _Basis:_ Never use binary floating-point for amounts: decoded numeric magnitudes are integer cents. Original encoding and signed storage are not verified. creastmt-sonnet.pdf pp.6,8-9: signed numeric pictures and two-decimal amounts; p.26: fixed-width inputs. Original copybook sign/encoding details are absent.
2. **LINES**: Accept LF or CRLF, remove one final record terminator, permit an empty file, and reject internal blank records or wrong record lengths. _Basis:_ File decoding is strict and never silently pads or drops a damaged record. creastmt-sonnet.pdf p.26: fixed-width text, one record per line. Newline conventions and malformed-record recovery are unspecified.
3. **INTERFACE**: Receive the four named raw file contents under files; return the two output line lists under their extensionless file names, plus assumptions.md and structured assumptions together. _Basis:_ No external filesystem, file gateway or customer delivery is implied. creastmt-sonnet.pdf p.26: a run may return the same lines as a list of strings under the file name without extension; file-gateway connection and publication destination are not supplied.
4. **CARD-DRIVER**: Generate one statement per cross-reference card sorted lexically by its fixed-width card number, rather than one pooled statement per account. _Basis:_ Two cards sharing an account receive separate statements. creastmt-sonnet.pdf p.2 BR-01: Statement driven by CardXref order (card number); p.4 scenario 1: One statement per card.
5. **TRANSACTIONS**: Select only transactions whose card number matches the current cross-reference and sort them by transaction ID; ignore transactions with no cross-reference. _Basis:_ Never pool another card's transactions, including cards sharing an account; unmatched transactions do not create statements. creastmt-sonnet.pdf p.2 BR-02: Transactions are keyed by card number + transaction id. Orphan-transaction treatment is not specified.
6. **PERIOD**: Do not apply a date/cycle or active-status filter. _Basis:_ All supplied matching transactions contribute, regardless of timestamps or account status. creastmt-sonnet.pdf p.3: legacy prints all transactions on file; confirm cycle filter requirement is a TODO. No active-status selection rule is stated.
7. **NAME**: Trim each name part and join nonempty first, middle and last names with one space. _Basis:_ Suppress blank name fragments; truncate the resulting text name to X(75). creastmt-sonnet.pdf p.4: verify address formatting; p.7 lists name fields; p.27 specifies customer name X(75). Name concatenation is unspecified.
8. **ADDRESS**: Use trimmed customer address lines 1 and 2 separately; join nonempty address line 3, state and ZIP with single spaces for the third printed address line. _Basis:_ Do not substitute account ZIP or print country. creastmt-sonnet.pdf p.21: address (3 lines, state, zip); p.27 provides three address slots. Exact concatenation, punctuation and account/customer ZIP precedence are not defined.
9. **FICO**: Render a blank customer FICO as 0; otherwise require three decimal digits and render the numeric value left-aligned in X(20). _Basis:_ No FICO lookup or recalculation occurs. creastmt-sonnet.pdf p.7: ficoScore is optional; p.27 requires FICO score X(20). Blank-value formatting is unspecified.
10. **TOTAL**: Sum signed transaction amounts in integer cents per card, with zero for no transactions; enforce a nine-digit integer magnitude for printed amounts. _Basis:_ Reject overflow instead of truncating money; negative transactions reduce the total. creastmt-sonnet.pdf p.2 BR-03: total expenditure = sum of amounts; p.4 scenario 4: card without transactions has zero total; p.27 amount pictures. Overflow treatment is unspecified.
11. **CONTENT**: Follow only the contract slots: omit SSN, country, phone, dates, credit limits and cycle totals; add no HTML expenditure-total block. _Basis:_ Both formats contain only the prescribed sections and fixed lines. creastmt-sonnet.pdf p.21 explicitly excludes SSN and mentions extra content; pp.27-29 define the output layouts without these extra slots or an HTML total block.
12. **PICTURES**: Use leading-zero 9(9).99- for current balance and leading-space Z(9).99- for transaction amounts and total; the final sign is minus only for negative values. _Basis:_ Do not introduce currency signs except the literal dollar slots in the text transaction/total rows. creastmt-sonnet.pdf p.27: picture notation and output positions.
13. **SEPARATORS**: Interpret repeated line numbers in the contract as annotations: retain every listed separator occurrence in sequence. _Basis:_ No blank lines or unlisted page breaks are inserted between concatenated statements. creastmt-sonnet.pdf p.27 repeats line labels 5,12,14 while prescribing lines in this order; pagination and between-statement spacing are unspecified.
14. **WIDTHS**: Truncate text fields to stated picture widths and right-pad final text records to 80 and HTML records to 100 characters. _Basis:_ Returned line lengths are exact, although the contract permits omitted trailing spaces. creastmt-sonnet.pdf pp.26-28: fixed-length records, X(n) pictures, trailing spaces may be omitted.
15. **HTML**: Escape inserted HTML text (&, <, >, double quote and apostrophe), then right-truncate any assembled HTML record longer than 100 characters. _Basis:_ Escaping may expand a field and truncation may cut markup; no undocumented wrapping or redesigned markup is added. creastmt-sonnet.pdf pp.27-29 specify literal HTML lines padded to 100; escaping and overlength-record behaviour are unspecified.
16. **INVALID**: Fail the entire batch on missing input files, malformed records, duplicate account/customer/card keys, duplicate card-plus-transaction keys, unresolved referenced account/customer, or numeric overflow. _Basis:_ Return an error identifying file/record context without raw records and publish no partial statements. creastmt-sonnet.pdf p.23 BR-02: A failing step stops the chain. Statement-level recovery and duplicate/missing-reference handling are unspecified.
17. **EMPTY**: Require all four file names even when empty; an all-empty set is a valid batch with two empty output lists. _Basis:_ An empty cross-reference file creates no statements. creastmt-sonnet.pdf p.26 lists the four inputs; p.2 makes cross-references the driver. Missing-file and all-empty outcomes are unspecified.
18. **DRAFTING**: Draft assumption prose with a model from these explicit facts only; preserve every identifier and exact source citation and send no customer record data. _Basis:_ The model cannot calculate, select or change statement contents. Maker requested each assumption and its wiki basis in assumptions.md; no prose-drafting mechanism is specified in the wiki.
19. **DRAFT-FAILURE**: Validate the draft's complete set of identifiers and exact source fields before publishing statements; on drafting failure return FAILED, no statements, and the explicit facts as diagnostic assumptions.md. _Basis:_ A missing or incomplete ledger cannot be mistaken for a complete statement run. Maker requires assumptions.md beside outputs; drafting failures and recovery are unspecified in the wiki.
