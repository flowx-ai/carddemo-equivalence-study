1. **LAYOUT-ACCOUNT**: Reconstruct CVACT01Y as contiguous fields: acct_id offset 0 width 11; active_status 11/1; curr_bal 12/12; credit_limit 24/12; cash_credit_limit 36/12; open_date 48/10; expiration_date 58/10; reissue_date 68/10; curr_cyc_credit 78/12; curr_cyc_debit 90/12; addr_zip 102/10; group_id 112/10. Ignore trailing filler. These offsets are unverified. _Basis:_ Account fields, pictures and 178-byte filler are listed, but the complete copybook is absent. intcalc-sonnet.pdf p.6 DT-01; p.24 CONTRACT.md
2. **LAYOUT-CATEGORY**: Reconstruct CVTRA01Y as account 0/11, type 11/2, category 13/4, signed balance 17/11; ignore remaining filler. Offsets are unverified. _Basis:_ DT-06 lists field order and S9(9)V99, not the full copybook. intcalc-sonnet.pdf p.9 DT-06; p.24 CONTRACT.md
3. **LAYOUT-RATE**: Reconstruct CVTRA02Y as group 0/10, type 10/2, category 12/4, signed rate 16/6; ignore remaining filler. Offsets are unverified. _Basis:_ DT-07 gives S9(4)V99; its five-character 0150{ example does not establish complete physical padding. intcalc-sonnet.pdf p.9 DT-07; p.24 CONTRACT.md
4. **LAYOUT-XREF**: Reconstruct CVACT03Y as card 0/16, ignored customer 16/9, account 25/11; ignore remaining filler. Offsets are unverified. _Basis:_ DT-04 lists field order and lengths; full copybook is absent. intcalc-sonnet.pdf p.8 DT-04; p.24 CONTRACT.md
5. **FRAMING**: Treat LF as the record separator, remove one CR before LF, ignore only the final newline terminator, and accept records when all consumed fields exist. Do not inspect filler bytes, including NUL or other non-printable bytes. _Basis:_ CONTRACT.md specifies one record per line; it does not prescribe newline encoding or validation of unused filler. intcalc-sonnet.pdf p.24 CONTRACT.md
6. **OVERPUNCH**: Decode final {ABCDEFGHI as positive digits 0 through 9 and }JKLMNOPQR as negative digits 0 through 9; a final ordinary digit is positive. Monetary fields and rates have two implied decimals. _Basis:_ The wiki identifies signed decimal pictures and gives 0150{ = 15.00, but not the full decoding table. intcalc-sonnet.pdf pp.6,9 DT-01/06/07
7. **TRUNCATION**: Use exact integer minor units and truncate each category interest toward zero: balanceCents times rateHundredths divided by 120000. Sum the resulting posted cents. _Basis:_ BR-03 gives balance times rate / 1200. BR-08 states default truncation but explicitly requests a golden-file rounding check. intcalc-sonnet.pdf p.2 BR-03/08; p.4 scenario 1
8. **ORDER**: Process account, type and category keys in ascending lexical order for repeatable transaction numbering. _Basis:_ The process groups balances by account; tie ordering within accounts is not defined. intcalc-sonnet.pdf pp.2-3 process flow/data mapping
9. **DUPLICATES**: Retain the first parsed occurrence of a duplicate account, category-balance key or disclosure-rate key and report the duplicate. Retain the first occurrence of a card number. _Basis:_ The data model declares primary/composite keys, but duplicate rows in supplied flat files have no specified resolution. intcalc-sonnet.pdf pp.6,8-9 primary/composite keys
10. **ACCOUNT-STAGING**: Stage each account independently. Any malformed category row identifiable to that account, missing rate, missing required card or sequence exhaustion leaves all that account transactions unposted and its original balances unchanged. Continue other accounts and mark the result PARTIAL. _Basis:_ The interest step has no complete failure/rollback specification; integrations describe not-found results and per-record bulk failures. intcalc-sonnet.pdf pp.16,18,20 error handling
11. **MISSING-DEFAULT**: An absent account-group rate retries DEFAULT; an explicit zero rate does not retry. If DEFAULT is also absent, report the category and leave that account unposted. _Basis:_ BR-02 defines missing-group fallback but says nothing about an absent DEFAULT row. intcalc-sonnet.pdf p.2 BR-01/02; p.18 missing disclosure group
12. **CARD-SELECTION**: For an account that needs an interest transaction, select its lexically first card number from cardxref.dat. If none exists, leave the account unposted. Zero-rate-only accounts do not require a card. _Basis:_ Card cross-reference fields and transaction card_num are specified, but the interest wiki gives neither card selection nor missing-card behaviour. intcalc-sonnet.pdf pp.8-9 DT-04/05; p.24 transaction fields
13. **UNTOUCHED-ACCOUNTS**: Return every valid input account. Accounts with no category rows keep all fields, including cycle totals, unchanged. Accounts whose categories all resolve reset both cycle totals, including zero-rate-only accounts. _Basis:_ BR-06 updates at account changes within category processing; behaviour for accounts absent from that stream is not stated separately. intcalc-sonnet.pdf p.2 BR-06; p.24 account output
14. **TRANSACTION-SEQUENCE**: Concatenate the ten-digit interestRunDate prefix and six-digit sequence starting at 000001. Assign numbers only when committing a successfully staged account; fail that account rather than wrap beyond 999999. Restart for every invocation. _Basis:_ BR-05 describes a parameter prefix and running suffix; DT-05 specifies a 16-character identifier. Start, width, overflow and restart details are not given. intcalc-sonnet.pdf p.2 BR-05; p.8 DT-05
15. **TIMESTAMPS**: Set both original and processed timestamps to business-date midnight in YYYY-MM-DD 00:00:00.000000 format. _Basis:_ The transaction model specifies two 26-character timestamps; the interest wiki does not specify their values. intcalc-sonnet.pdf p.9 DT-05; p.24 run parameters
16. **MERCHANT-DEFAULTS**: Use merchant_id 0 and blank merchant_name, merchant_city and merchant_zip for generated interest transactions. _Basis:_ BR-04 specifies system source and description, but does not initialize merchant fields required by the output contract. intcalc-sonnet.pdf p.2 BR-04; p.24 transaction fields
17. **ZERO-AMOUNTS**: A nonzero annual rate emits a transaction even when its interest truncates to 0.00; only a zero rate suppresses it. _Basis:_ The documented branch checks rate not zero rather than amount not zero. intcalc-sonnet.pdf p.2 process flow/BR-03; p.4 scenario 5
18. **RUN-OUTPUTS**: Return fresh arrays each invocation and do not persist or append across invocations. No files were written. _Basis:_ BR-09 contrasts legacy overwrite with FlowX append; the accepted partial-delivery scope returns datasets without storage. intcalc-sonnet.pdf p.2 BR-09; p.24 CONTRACT.md; maker delivery-scope answer
19. **STEP-ISOLATION**: Use supplied account and category contents as already posted. Do not run POSTTRAN. Other contract files not consumed by interest are optional and ignored. _Basis:_ CONTRACT.md isolates INTCALC using oracle POSTTRAN outputs; the documented formula needs account/category/rate data and transaction card linkage. intcalc-sonnet.pdf p.24 step isolation; pp.2,8-9
20. **BATCH-WINDOW**: Do not enforce scheduling or a batch-window flag in this isolated calculation. _Basis:_ The flag belongs to the surrounding chain and online access policy remains a TODO; this request is one step. intcalc-sonnet.pdf pp.21-23 end-of-day-batch-chain

Missing consumed file contents is INVALID_INPUT; empty supplied files are allowed. _Basis:_ CONTRACT.md supplies those run values but no command-line or missing-file interface. Defaults and interface checks are this implementation choices. intcalc-sonnet.pdf p.24 run parameters; p.3 start data

Invalid coverage, references or Markdown use a canonical log instead. Accounting is never model-generated. _Basis:_ The maker requests source-linked assumptions; neither the wiki nor CONTRACT.md prescribes an explanation-generation mechanism. maker assumptions.md request and accepted implementation description
