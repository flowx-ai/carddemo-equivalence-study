# Assumption ledger (extracted verbatim from the workflow scripts' fact() calls)

1. **rounding**: Truncate each category interest toward zero to cents before adding posted interest to the account. _Basis:_ intcalc-sonnet.pdf p.2 BR-08 says COBOL default truncation but explicitly asks to confirm truncate versus ROUNDED; p.4 asks to verify two decimals.
2. **account-layout**: Use zero-based account offsets: id 0/11, status 11/1, current balance 12/12, credit limit 24/12, cash limit 36/12, dates 48/10, 58/10, 68/10, cycle credit 78/12, cycle debit 90/12, ZIP 102/10, group 112/10. Ignore remaining filler. _Basis:_ intcalc-sonnet.pdf pp.6,24 list ordered CVACT01Y fields, widths and 300-byte records, but do not reproduce the full copybook. Offsets are inferred from that order.
3. **balance-layout**: Use category-balance offsets account 0/11, type 11/2, category 13/4, signed balance 17/11; ignore remaining filler. _Basis:_ intcalc-sonnet.pdf pp.9,24 list CVTRA01Y fields and a 50-byte record, without its full copybook.
4. **rate-layout**: Use disclosure offsets group 0/10, type 10/2, category 12/4, signed annual rate 16/6; trim surrounding spaces in that numeric field. _Basis:_ intcalc-sonnet.pdf p.9 declares S9(4)V99 but its example 0150{ contains only five characters. The six-character field is inferred from the declared picture; complete layout is absent.
5. **xref-layout**: Use cross-reference offsets card 0/16, customer 16/9, account 25/11; ignore remaining filler. _Basis:_ intcalc-sonnet.pdf p.8 lists CVACT03Y fields in this order; p.24 gives 50 bytes. Complete copybook is absent.
6. **numeric-encoding**: Read implied cents and signed trailing overpunch: {ABCDEFGHI means positive digits 0-9 and }JKLMNOPQR means negative digits 0-9. Also accept plain digits or an explicit leading sign. Retain identifiers as strings until contract serialization. _Basis:_ intcalc-sonnet.pdf pp.6,8-9 specify signed decimal pictures and the positive overpunch example; other sign encodings are not enumerated. p.24 requires integer account identifiers in JSON.
7. **balance-order**: Process balances sorted by account, type and category; ties keep input order and duplicate balance rows are each processed. _Basis:_ intcalc-sonnet.pdf p.2 describes per-account category processing and account-change updates. The order for unsorted or duplicate input rows is not specified.
8. **sequence**: Number emitted transactions from 000001 using six digits after the ten-character run parameter; reset on every invocation and skip/report records after 999999. _Basis:_ intcalc-sonnet.pdf p.2 BR-05 specifies the run-date prefix plus a running suffix; p.8 specifies a 16-character transaction ID. Initial suffix, width, reset and exhaustion handling are not stated.
9. **card-selection**: Use the lexicographically lowest associated card number for an account. _Basis:_ intcalc-sonnet.pdf pp.2,8 require interest transactions and a card number, but do not specify which card to choose when an account has several.
10. **missing-card**: Use a blank card number when no cross-reference exists; do not suppress otherwise calculable interest. _Basis:_ intcalc-sonnet.pdf pp.2,8,24 do not define the missing-card case for interest transactions.
11. **merchant-values**: Set merchant_id to integer zero and merchant_name, merchant_city and merchant_zip to empty strings. _Basis:_ intcalc-sonnet.pdf pp.2,8,24 require merchant fields in output but give no interest-specific values.
12. **timestamps**: Set both timestamps to business-date midnight as YYYY-MM-DD HH:mm:ss.000000; default business date is 2022-07-18. _Basis:_ intcalc-sonnet.pdf pp.8-9 specify X(26) timestamps, and p.24 gives the business date, but no interest-transaction timestamp or timezone rule.
13. **account-scope**: Reset cycle totals only on accounts with at least one successfully processed balance, including a zero-rate balance; preserve other accounts and return every supplied account row. _Basis:_ intcalc-sonnet.pdf p.2 BR-06 describes updates at account changes; p.24 requires every account after interest. Accounts without category balances are not discussed.
14. **account-status**: Do not add an active-status eligibility filter. _Basis:_ intcalc-sonnet.pdf p.2 says for each account/type/category balance and supplies no inactive-account exclusion.
15. **missing-account**: Report and skip a balance with no uniquely usable account record. _Basis:_ intcalc-sonnet.pdf pp.2,17-18 do not define an orphan category-balance policy.
16. **missing-rate**: When the group row is absent, try DEFAULT; if both are absent or a selected rate is malformed, report and skip the balance without inventing a rate. A malformed group row is not the same as an absent row. _Basis:_ intcalc-sonnet.pdf p.2 BR-02 and pp.17-18 specify fallback on not found, but no exhausted-fallback or malformed-rate behaviour.
17. **malformed-records**: Report and isolate malformed consumed fields. Preserve malformed account rows as far as representable and do not calculate against their invalid current balance. Do not inspect filler or unused fields. A result containing such records is partial, not certified contract-valid. _Basis:_ intcalc-sonnet.pdf pp.6-9,24 specify layouts but give no malformed-input policy.
18. **duplicate-lookups**: Use the first account, disclosure or card cross-reference row for an identical lookup key, report duplicates, and preserve all supplied account rows in output. _Basis:_ intcalc-sonnet.pdf pp.6,8-9 describe primary/composite keys but do not specify duplicate sequential-input handling.
19. **input-presence**: Require text contents for acctdata.dat, tcatbal.dat, discgrp.dat and cardxref.dat, permitting empty files. Missing contents or invalid run parameters return FAILED without financial result lists. Ignore the other contract inputs for this isolated step. _Basis:_ intcalc-sonnet.pdf p.24 lists shared chain inputs and isolates INTCALC on POSTTRAN account and category-balance outputs; it does not specify missing-file handling.
20. **line-endings**: Split on LF or CRLF and remove one terminal line separator. Ignore filler after consumed fields rather than rejecting records based on filler contents or absent trailing filler. _Basis:_ intcalc-sonnet.pdf p.24 says one record per line and fixed widths but does not specify newline conventions or filler validation.
21. **transaction-presence**: Create a transaction whenever the selected rate is nonzero, even if the truncated amount is zero; do not generate fees. _Basis:_ intcalc-sonnet.pdf p.2 BR-03 gates on rate not zero, not computed amount; BR-07 describes an empty fees stub. p.4 flags the optional fee enhancement as undecided, so legacy behaviour is retained.
22. **output-replacement**: Return only transactions generated by this invocation, not existing transactions; retain a complete account snapshot. _Basis:_ intcalc-sonnet.pdf p.2 BR-09 contrasts legacy overwrite with FlowX append, but p.24 defines isolated interest outputs and supplies no previous system-transaction output to append to.
23. **arithmetic-range**: Use exact decimal integer operations without floating-point rounding; do not emulate unspecified COBOL overflow effects. _Basis:_ intcalc-sonnet.pdf p.2 gives the formula and truncation uncertainty but does not describe overflow handling.
24. **report-policy**: Draft explanations only from this register; preserve every canonical assumption and citation and fall back to the complete canonical report if drafting fails or returns invalid or missing entries. Financial results never depend on drafting. _Basis:_ The maker requests each decision with its wiki basis. intcalc-sonnet.pdf does not specify report drafting or its failure policy; this is an implementation assumption.
