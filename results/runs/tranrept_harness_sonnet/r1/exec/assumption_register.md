# Assumption ledger (extracted verbatim from the workflow scripts' assumption() calls)

1. **delivery**: Accept the four named files as text in the run input and return report lines and assumptions.md in the same output bundle, not as physical disk writes. _Basis:_ CONTRACT permits a list of strings under the report file name without extension; no external filesystem is specified. 26
2. **transaction-offsets**: Read transact.dat at 1-based positions: ID 1-16, type 17-18, category 19-22, source 23-32, description 33-132, amount 133-143, merchant ID 144-152, name 153-202, city 203-252, ZIP 253-262, card 263-278, original timestamp 279-304, processed timestamp 305-330, filler 331-350. _Basis:_ The Transaction attributes and widths are listed, but the complete CVTRA05Y copybook is absent; sequential offsets and final filler are inferred. 8-9
3. **xref-offsets**: Read cardxref.dat as card 1-16, customer 17-25, account 26-36 and filler 37-50. _Basis:_ CardXref lists these three attributes and widths; CONTRACT gives 50 bytes, but the complete copybook is absent. 8,26
4. **reference-offsets**: Read trantype.dat as type 1-2, description 3-52, filler 53-60; trancatg.dat as type 1-2, category 3-6, description 7-56, filler 57-60. _Basis:_ Reference attribute order and widths plus 60-byte record lengths are supplied; complete copybooks are absent. 9-10,26
5. **encoding**: Require decoded ASCII text. An amount is eleven implied-cent digits; its final character may be an ASCII positive {ABCDEFGHI or negative }JKLMNOPQR overpunch, or an ordinary positive digit. _Basis:_ Transaction amount is S9(9)V99 and disclosure data mentions signed overpunch, but transaction file encoding is not specified. 8-9
6. **line-endings**: Accept LF or CRLF separators; ignore only the final empty segment from a terminal newline. All other records must have the exact declared width; an entirely empty file has zero records. _Basis:_ CONTRACT says fixed-width text, one record per line, without specifying newline conventions or treatment of empty records. 26
7. **default-dates**: Default to 2022-07-01 through 2022-07-31; explicit startDate and endDate independently override those defaults. _Basis:_ CONTRACT supplies these dates; the earlier wiki gives 2022-01-01 through 2022-07-06 and permits per-run overrides. 2-3,26
8. **date-comparison**: Use the first ten processing-timestamp characters as a Gregorian YYYY-MM-DD date, inclusive at both boundaries, without timezone conversion. _Basis:_ BR-01 filters on processedTimestamp between the start and end dates inclusive; no timezone or time-of-day boundary policy is stated. 2
9. **tie-order**: Sort ascending by card number and preserve input-file order for equal cards; do not deduplicate transactions. _Basis:_ BR-02 says sorted by card number; tie ordering and deduplication are not specified. 2
10. **identifier-format**: Preserve leading zeros in identifiers and print the eleven-character account identifier from CardXref, not a numeric reformatting. _Basis:_ Identifiers are string fields, and the printed account position has eleven columns. 8-9,29
11. **lookup-keys**: Resolve account by card number, type by type code, and category by the combination of type and category code. _Basis:_ CardXref is keyed by card and TransactionCategory has a type-plus-category key; the document plugin requires account and reference descriptions. 8-10,19
12. **grouping**: Print an Account Total at each card break even if multiple cards resolve to the same account. _Basis:_ The plugin describes an account/card total with a break on card number. 19
13. **page-capacity**: A page holds fifty detail records; headers, rules and total lines do not consume this capacity. _Basis:_ The wiki explicitly leaves lines per page as TODO. 19
14. **page-order**: Repeat the four-line page opening. At coincident boundaries print account total and rule before page total and rule; continue a card subtotal across pages; print the grand total last without a following rule. _Basis:_ CONTRACT specifies page openings and rules following page/account totals, but not page capacity or ordering of coincident boundaries. 19,29
15. **empty-selection**: An empty selection prints the four-line page opening, a zero page total, its rule and a zero grand total, with no account total. _Basis:_ The empty-range scenario requires a report with zero total; detailed empty-report layout is not stated. 4,29
16. **page-number**: Do not print a page number or extra title fields. _Basis:_ The plugin mentions a page number, but the authoritative CONTRACT header allocates no position for one. 19,29
17. **money**: Compute all sums in signed integer cents; require exact safe-integer arithmetic; fail any displayed value exceeding 999999999.99 rather than round or truncate. _Basis:_ The wiki requires page/card/grand totals and CONTRACT fixes two-decimal pictures; overflow behaviour is unspecified. 2,27,29
18. **picture-zero**: Print two fractional digits, suppress zero integer digits and their leading commas, put a minus or space in the first position for details, and an explicit plus or minus for totals. _Basis:_ CONTRACT gives sign and leading-zero picture notation; use its two-decimal interpretation also at zero. 27,29
19. **text-fields**: Truncate reference descriptions to fifteen and twenty-nine characters and space-pad every printed line to 133 columns; do not print the transaction free-text description. _Basis:_ CONTRACT allocates X(15), X(29) and a 133-column line; truncation handling is not separately stated. 29
20. **missing-lookups**: Continue a missing type or category with UNKNOWN in its description position; continue a missing cross-reference with a blank account ID. Record each missing lookup by file and record number. _Basis:_ The acceptance scenario flags a missing type and continues; placeholder wording and missing-category/cross-reference behaviour are not stated. 4
21. **bad-input**: Fail missing files, non-ASCII data, invalid record widths, malformed required numeric keys, invalid Gregorian dates or amount encodings, inverted ranges and duplicate reference keys. Return no partial report, but return assumptions.md with the failure reason. _Basis:_ CONTRACT specifies input formats but no malformed-input or duplicate-reference policy. 8-10,26
22. **validation-scope**: Validate all records before selection, including excluded transactions, without modifying any inputs or upstream account data. _Basis:_ Step isolation is specified; whether malformed excluded transactions are ignored is not stated. 26
23. **drafting**: A model drafts the structured assumption entries from this register and supplied wiki extracts only; it receives no transaction records. Report generation is deterministic and independent of its answer. _Basis:_ The request requires each assumption and its wiki basis, but does not prescribe how to compose the document. 1-29
24. **draft-fallback**: Accept model entries only if every decision ID, assumption, wiki basis and source is preserved exactly. Otherwise render this canonical register and disclose the fallback. _Basis:_ The request requires a complete source-linked assumptions document; drafting-failure behaviour is not specified. 1-29
